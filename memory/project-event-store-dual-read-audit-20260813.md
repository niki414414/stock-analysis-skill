# 事件库双读差异审计（2026-08-13）

## 结论

SQLite 影子库已通过完整性与外键检查；双读差异主要来自两种查询语义不同，不是漏导入：旧公司池按公司静态产业标签做宽召回，SQLite 按正式的“公司—事件”关系做事件召回。两者不应追求数量完全相等。旧池负责候选覆盖，SQLite 负责解释当前催化；进入波段候选后仍交由六层分析。

本轮修复了两条无正式事件支撑的科技 mapping，以及三条非科技 forward 空 ID 行。审计异常由 38 条降至 33 条，余下均为科技库早期信号、来源和前瞻表中的历史碎片，已隔离为 `legacy_fragment`，不参与正式事件关系查询。

## 三个赛道双读

| 赛道 | 旧池 | SQLite | 差异解释 |
|---|---:|---:|---|
| AI应用 | 64 | 57 | 旧池独有 12 家主要是游戏与 AI4S/CXO 的静态跨界标签；SQLite 独有 5 家来自已登记事件关系，但旧池的文字字段未被“AI应用”关键词命中。属于分类口径差异。 |
| 半导体 | 103 | 124 | 旧池独有 17 家是宽口径半导体设计、设备、材料公司；SQLite 独有 38 家包含封测、分销、功率器件、上游材料及光芯片等已关联具体事件的跨赛道公司。属于事件链映射比静态标签更宽。 |
| 医药 | 36 | 15 | 旧池独有 21 家涵盖创新药、CXO、器械、流通等静态医药样本；SQLite 只返回已有正式事件关系的 15 家，因此更窄。属于“产业覆盖池”和“当前催化池”的边界差异。 |

代表性差异：AI应用旧池独有恺英网络、三七互娱、药明康德、百奥赛图，SQLite 独有视觉中国、三六零；半导体旧池独有深科技、韦尔股份、江波龙，SQLite 独有通富微电、长电科技、华润微、源杰科技；医药旧池独有恒瑞医药、科伦药业、凯莱英、百济神州，SQLite 无反向独有项。

## 使用规则

1. 需要“板块里有哪些公司”时，用旧公司池宽召回。
2. 需要“哪些公司被当前事件支撑”时，用 SQLite 正式关系召回。
3. 早期信号不得为了消除差异而伪造正式事件或 mapping；等事实验证后再升级。
4. 双读差异只要求可解释。只有同一正式事件 ID、同一公司关系在两端矛盾，才判定为迁移缺陷。
