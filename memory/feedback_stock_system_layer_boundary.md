# 股票系统分层边界（2026-08-03）

## 长期原则

所有股票相关修改都必须放回完整系统判断，不允许只优化单个脚本或数据库：

```text
研究材料 → 事件地图 → 公司召回/候选筛选 → 六层个股分析 → 操作决策
```

新增字段或规则前必须确认它属于哪一层、谁写入、谁消费，以及是否与下游重复。一个字段
只被计算或保存、没有进入正式工作流，不算集成完成。

## 层级职责

- 研究材料：保留原始事实和上下文，作为新增事件及公司关系的输入。
- 事件地图：验证事件、产业影响、产业角色、后续指标和风险。
- 公司召回：保存公司为何进入候选的最小关系事实，不产生买入信号。
- 六层个股分析：实时核验公司业务占比、商业化、订单/利润、财务、估值、趋势、买点和量能。
- 操作决策：把六层结论转成可观察条件与执行动作。

## 公司—事件关系口径

事件库关系字段仅包括：产业角色、`relation_status`、`benefit_tier`、`mapping_basis`、
`mapping_confidence`、`source_ref`、验证指标/风险和`last_verified`。

- `映射已验证 / 明确映射`：已验证产业mapping明确列出该公司；证明公司是正式召回样本，
  不等于已经确认收入占比或利润兑现。
- `已登记 / 角色关联`：公司池已登记到正式事件和产业角色；需要六层第三层进一步核验。
- `已登记 / 主题观察`：公司池原文明确写有映射、参股、概念或生态，只作低层级召回。
- “已登记”关系保留公司池来源批次，但`last_verified`必须留空；不得用导入日期冒充验证日期。
- 公司池原“置信度”只表示映射置信度，不得改称证据等级。

事件关系表不保存`commercial_stage`、`benefit_directness`或综合`evidence_grade`。商业化阶段、
收入利润贡献和当前交易判断具有公司特异性和时效性，应在六层分析时查询；如需复用，应
另存带观察日期和有效期的分析快照，不能覆盖为公司静态属性。

## 材料提及

材料—公司提及只作为增量发现和待审核队列，不是数据库切换的硬门槛。未经确认的提及
不得进入正式公司—事件关系，也不得被筛选器当成已验证候选。
