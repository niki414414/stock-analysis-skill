做任何框架性改动前，必须执行以下步骤，不可跳过：

1. **回顾框架的目标或分层目标**：这个改动服务于哪一层？那一层的目的是什么？
2. **多维度分析候选方案**：至少从"回答的问题是否准确"、"是否有循环/偏差"、"复杂度"、"跨场景一致性"几个维度对比
3. **选择最合乎的方案**：不是最完美的，是在框架目标下最有意义的
4. **奥卡姆剃刀**：整个框架坚持最简解——能用一个指标解决的，不用两个；能用现有工具的，不新增工具

**Why:** 用户观察到改动往往直接跳到实现，没有先想清楚为什么，导致方案设计偏离框架真实目的。

**How to apply:** 每次用户说"改一下xxx"或"加一个xxx功能"，先输出"框架目标回顾+方案对比"再动手，除非改动明显是笔误/小修复。

**实例（2026-06-08）：**
周校准ETF选择问题，通过回顾"校准目的=判断stage标签是否过期=资本配置问题"，得出：
信号股20日超额收益（vs创业板ETF）比"信号股vs赛道ETF"更准确回答问题，
且一个指标同时包含绝对趋势和相对资金流向，符合奥卡姆剃刀。
