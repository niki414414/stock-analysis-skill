2026-07-21激活`/market-outlook`（见[[project-layer4-market-state-alignment]]同批工作）后，"情景→动作翻译表"里的概率数字（比如"修复延续~40%/高低切换~40%/反弹夭折~20%"）目前是人工估的定性权重，不是像`regime_label`历史胜率表那样有回测支撑。

**背景**：当天做了一次窄口径回测（创业板指2015-2026"前5日跌≥5%+当日涨≥6%"精确匹配"反转型普涨"，n=4），发现历史表现明显弱于、且方差明显大于`market-state-machine.md`原有的"普涨"整体胜率(58.8%)，已把这个发现写进`market-state-machine.md`"反转型普涨"专项说明和`market_thesis.md`假设#11。这次的单因子回测证明"规模小但做对了方法"是有价值的，但样本量(n=4)太小，不足以支撑一个正式的概率数字。

**用户明确要求**：下周专门设计一个多因子回测，把当天(2026-07-21)新增的几个字段都纳入联合条件——两融变化趋势、护盘ETF份额跳升(`national_team_proxy`)、两市合计成交量放大幅度(`total_turnover`)、背离占比(`divergence_ratio`)，而不是只用"regime_label是否普涨"这一个维度去筛历史样本。目标是让"情景→动作翻译表"的概率数字从人工估计升级为有回测支撑的数字。

**Why：** 目前的概率纯粹是定性权重，跟华泰"70%胜率"这类只讲结论不讲方法的数字本质上是一类东西——按用户一贯的"经典理论+验证+回测"原则，这块迟早要补，用户自己也在当天指出了这个缺口。

**How to apply：** 用户下次说"设计这个回测"或类似意思时，直接从这条memory接上。需要先确定：①多因子联合筛选的具体阈值怎么定（两融变化/ETF跳升幅度/成交量放大幅度都要有明确数字门槛，不能凭感觉）②样本区间用多长（当前A股不同regime下的数据可能不够多，参考`market-state-machine.md`用过的849交易日/2023-2026做法）③怎么处理"多因子组合样本量会更稀少"这个必然出现的问题（可能需要放宽个别因子阈值换取样本量，或接受样本小但如实报告置信区间宽）。走`/update-framework`验证纪律，先测出结果再决定要不要把新概率数字写进`market-state-machine.md`正式文件。
